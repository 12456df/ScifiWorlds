## 独立开发原则

- 优先完成可运行、可测试、可提交的游戏功能，不为多人团队流程增加额外管理开销。
- 不维护额外的 Must/Should/Could 优先级矩阵；开发顺序由模块依赖和垂直切片目标决定。
- 技术规范、网络正确性、可维护性和必要文档不能因独立开发而省略。
- 商业模式、正式发行日期和非阻塞产品选项在需要时再确定。

## 工作项规则

- 功能系统的执行顺序、依赖和 Commit 门槛以 [模块开发路线图](07_DevelopmentRoadmap.md) 为准。
- 每个工作项必须关联模块和验收标准；默认负责人为独立开发者。
- 工作开始前满足 Definition of Ready。
- 工作完成时满足 Definition of Done。
- 新增范围必须说明对日期、成本和质量的影响。

## Definition of Ready

- [ ] 目标与玩家价值明确
- [ ] 验收标准可测试
- [ ] 依赖和负责人明确
- [ ] 所需资源与授权已确认

## Definition of Done

- [ ] 实现完成并通过编译
- [ ] 验收标准全部通过
- [ ] 必要测试和性能检查完成
- [ ] 文档同步更新
- [ ] 已通过代码/资产评审
