# ScifiWorlds 技术开发规范

**状态：** Approved
**适用范围：** C++、蓝图、GAS、多人网络、Dedicated Server、技术文档与代码评审
**最后更新：** 2026-07-20

## 1. 技术基线

- 引擎基线为 Unreal Engine 5.7。
- 核心玩法框架采用 Gameplay Ability System（GAS）。
- 游戏从立项起按多人联机、服务器权威和 Dedicated Server 目标设计。
- 开发采用 C++ 与蓝图混合模式，并明确职责边界。
- 技术方案必须优先保证健壮性、可扩展性、可读性和可维护性，避免过度耦合。

## 2. 架构原则

### 2.1 契约优先

- 新系统先完成问题、需求、边界、数据所有权、接口和事件设计，再进入实现。
- 公共接口必须说明输入、输出、副作用、前置条件和后置条件。
- 跨系统访问依赖稳定契约，不依赖另一个系统的内部实现。

### 2.2 单一职责与数据所有权

- 每个系统只负责一个清晰领域，并且拥有自己写入的状态。
- 一个运行时状态只能有一个权威写入者；其他系统通过只读查询或事件观察。
- 编排逻辑放在明确的协调层，不允许形成 God Object、万能 Manager 或隐式全局控制器。

### 2.3 显式、单向、可替换的依赖

- 模块和系统依赖必须显式声明，并尽量形成有向无环图（DAG）。
- 跨系统通信优先使用接口、委托、Gameplay Tags 或定义明确的消息/事件。
- 禁止通过任意 `GetGameInstance()`、全局单例、对象查找或蓝图强制转换建立隐藏依赖。
- 发生循环依赖时，应抽取共享契约或重新分配职责，不使用互相持有来规避设计问题。

### 2.4 数据驱动

- 角色、技能、装备和数值配置优先放入 Data Asset、Data Table、Gameplay Effect 或配置文件。
- 不在逻辑代码和蓝图图表中散落魔法数字、硬编码资产路径或角色特例。
- 角色差异通过配置、组合与可替换策略表达，避免复制整套系统代码。

## 3. C++ 与蓝图职责边界

### C++ 负责

- 稳定的 Gameplay Framework、系统契约和基础类型。
- GAS 基类、ASC 初始化、AttributeSet、Gameplay Tags 与网络权威逻辑。
- 复制状态、RPC 校验、预测边界和 Dedicated Server 兼容逻辑。
- 性能敏感、需要自动化测试或会被多种内容复用的逻辑。
- 对蓝图暴露窄而稳定的 API，不直接暴露可破坏内部不变量的可写状态。

### 蓝图负责

- 基于 C++ 契约进行角色、技能、装备和表现内容配置。
- 动画、VFX、音频、UI、关卡组装及快速内容迭代。
- 不影响权威结果的表现层编排。

### 蓝图不得负责

- 决定服务器权威的伤害、资源、胜负、装备购买或永久状态。
- 绕过 GAS/系统契约直接修改其他对象拥有的数据。
- 通过大量 Cast、跨层硬引用或关卡蓝图承载核心游戏规则。
- 复制一份 C++ 已实现的规则，形成两个行为来源。

## 4. GAS 规范

- GAS 是角色技能、属性、消耗、冷却、Buff/Debuff 和技能状态的统一框架。
- 玩家 ASC 的宿主、Avatar 生命周期与复制模式必须在实现前通过系统设计或 ADR 确定；多人重生场景默认优先评估 PlayerState 持有 ASC 的方案。
- ASC 必须在服务器与客户端的正确生命周期中初始化，之后才能授予能力或应用初始 Gameplay Effect。
- Gameplay Ability 负责行为编排；Gameplay Effect 负责数据驱动的属性变化；AttributeSet 负责有明确所有权的属性集合。
- 技能状态、阻断、取消和输入映射使用分层 Gameplay Tags，代码引用优先采用 Native Gameplay Tags。
- 玩家主动技能只在适合预测时使用 GAS 的预测能力；权威结果仍由服务器确认。
- Gameplay Cue 只承担表现，不得改变权威玩法状态。
- 技能无论成功、失败、取消或 Avatar 销毁，都必须正确结束并清理 Ability Task、委托和临时状态。
- 装备对技能的伤害、持续时间、范围、冷却和次数修正必须数据驱动，并明确叠加顺序、上下限和不适用规则。

## 5. 多人网络规范

- 服务器是游戏状态、伤害、资源、装备交易、生成、死亡、塔/水晶状态和胜负的唯一权威。
- 客户端发送意图，不发送可信结果；所有影响玩法的请求都必须在服务器验证所有权、状态、范围、资源和频率。
- 持久状态使用属性复制或 GAS 复制，不使用 NetMulticast 代替状态同步；表现事件可以使用不可靠 Multicast 或 Gameplay Cue。
- PlayerController 仅用于服务器与所属客户端可见的数据；所有玩家可见的状态放在 Pawn、PlayerState、GameState 或专属复制对象中。
- `OnRep`、重连、重新相关和休眠唤醒逻辑必须幂等，允许同一状态被重复应用而不产生副作用。
- 需要同步的大型集合应评估 `FFastArraySerializer`；高频数据应评估量化、条件复制、相关性、优先级和休眠。
- Dedicated Server 是一等运行环境。代码不得依赖本地玩家、Viewport、HUD、音频设备或仅客户端存在的对象。
- 从首个可玩切片开始执行 DS + 多客户端验证，覆盖加入、离开、死亡、重生、晚加入和比赛结束。

## 6. 质量属性

### 健壮性

- 对外输入、服务器 RPC、资源引用和配置进行校验；非法状态应尽早失败并留下可诊断日志。
- 对可恢复异常使用 `ensure`/日志，对违反不可恢复不变量的开发错误使用 `check`；具体断言策略后续统一。
- 生命周期清理必须与初始化对称，避免悬空委托、重复绑定、计时器泄漏和晚到网络回调。
- 必须设计空引用、连接中断、Avatar 更换、重复事件和晚加入等边界情况。

### 可扩展性

- 新角色、新技能、新装备优先通过数据和组合扩展，不修改共享核心流程。
- 公共契约保持最小化；新增能力不得迫使无关系统依赖具体实现类。
- 对不可逆或跨多个系统的架构改变建立 ADR。

### 可读性

- 遵循 Epic UE 命名、反射宏和 Public/Private 目录规范。
- 文件、类和函数命名表达职责；函数保持单一抽象层级。
- 注释解释“为什么”和约束，不重复代码已经说明的“做什么”。
- 蓝图图表按职责拆分函数/宏，保持清晰执行流，不使用超大 Event Graph。

### 可维护性

- 任何行为只有一个权威实现来源，避免 C++ 与蓝图重复规则。
- 修改系统契约时同步更新设计文档、测试和调用方。
- 技术债务进入 TDD 登记，不用永久 TODO 隐藏范围和风险。
- 重构不得改变外部行为，行为变化必须有需求和验收标准。

## 7. 参考资料与证据优先级

解决技术问题时按以下顺序取证：

1. `ScifiWorlds` 当前源码、`AGENTS.md`、`.agents/ue-project-context.md`、TDD、ADR 和系统设计文档，用于确认本项目事实与既有行为。
2. Epic 官方 Unreal Engine 5.7 文档和本机 UE 5.7 引擎头文件/源码，用于确认引擎 API 与运行行为。
3. `E:/Unreal Projects/Aura/Source/Aura/`，用于参考已有 GAS、输入、UI 和多人相关实现模式。
4. Aura 的 `.docs/GAS-Tranek-Documentation.md` 与多人学习文档，用于补充架构和实践细节。

规则：

- Aura 是参考实现，不是 ScifiWorlds 的代码依赖或事实来源。
- 参考 Aura 前先读取其 `AGENTS.md` 与 `.agents/ue-project-context.md`，再检查相关源码。
- Aura 或第三方资料与 UE 5.7 官方文档/引擎源码冲突时，以 UE 5.7 官方行为为准。
- 不盲目复制代码；必须重新确认所有权、生命周期、模块依赖、网络角色和本项目契约。
- 外部文档支撑关键技术结论时保留链接；从 Aura 源码推导的结论应明确标为项目实现推断。

## 8. 技术 Definition of Done

- [ ] Development Editor 构建通过，无新增编译警告
- [ ] Dedicated Server 与至少两个客户端完成受影响流程验证
- [ ] 服务器权威、客户端预测和表现层职责没有混淆
- [ ] 断线、死亡/重生、取消、晚加入等相关边界情况已验证
- [ ] 新增配置为数据驱动，不包含未登记的魔法数字或硬引用
- [ ] 系统不存在新增循环依赖或隐藏跨层访问
- [ ] 自动化测试或可重复的功能测试步骤已补充
- [ ] 相关 TDD、系统设计、ADR 和 UE 项目上下文已同步

## 9. 禁止的反模式

- God Object / 万能 Manager
- 客户端直接决定权威玩法结果
- 用 Multicast 保存持久状态
- C++ 与蓝图各自维护一套相同规则
- 跨系统直接写入他人数据
- 为方便而建立循环依赖或无边界全局单例
- 在 Character、PlayerController 或 Level Blueprint 中堆积无关系统职责
- 未验证生命周期和网络角色便照搬 Aura 或网络示例代码
